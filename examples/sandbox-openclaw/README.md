# sandbox-openclaw

A production-oriented sample showing how to run OpenClaw on Vercel Sandbox through Sandkit.

Read order for understanding the example boundary split:

- `lib/openclaw-service.ts`
  Public facade used by the API and workflow (`readState`, `createWorkspace`, `startSession`, `extendSession`, `commitSession`) and shared response-shape helpers.
- `lib/openclaw-app.ts`
  Composition root: `getOpenClawRuntime()` creates/validates the sqlite-backed drizzle client, builds the Sandkit app and exposes config.
- `lib/openclaw-store.ts`
  All durable `openclaw_sessions` and workspace-summary read/write operations.
- `lib/openclaw-sandbox.ts`
  All long-lived session path logic: bootstrap/rebuild, session attach/lease handling, gateway probe/repair/readiness, and process wiring.
- `app/api/openclaw/route.ts`
  Thin HTTP adapter that dispatches request actions directly to the service facade. No extra business logic.
- `workflows/openclaw-start-session.ts`
  Workflow adapter that only calls `startSession()` and emits workflow events.

- Creates a single OpenClaw workspace once.
- Keeps sandbox bootstrapping in durable `runCommand()` commands.
- Distinguishes bootstrap/session lifecycle:
  - bootstrap lives in durable `sandkit.workspace.sandbox` operations and DB summaries,
  - live runtime is handled through `openSession()`/`attachSession()` with lease-based recovery.
- `createWorkspace()` performs bootstrap with the default workspace policy (npm install)
  and `startSession()` switches to `aiGateway()` before launching, so outbound
  OpenClaw calls get policy-injected `AI_GATEWAY_API_KEY` and no real key is
  written into `openclaw.json` by bootstrap, repair, or control-ui rewrite.
  `aiGateway()` derives allowed hosts from the hostname of the configured AI gateway URL
  (currently `https://ai-gateway.vercel.sh/v1`, so `ai-gateway.vercel.sh`).
- `db/schema/sandkit.ts` is generated by `sandkit generate` (core schema only):
  `sandkitWorkspaces` / `sandkitRuns` / `sandkitPolicies`.
  It intentionally keeps `metadata` as untyped JSON so generator output stays
  idempotent.
- OpenClaw extension is app-specific in `db/schema/openclaw.ts`:
  `openclawSessions`.
- `db/schema/index.ts` is the non-generated composition entrypoint used by
  `drizzle.config.ts` and keeps this generated/app overlay split explicit.
- `openclaw_sessions` stores durable bootstrap/session progression, while
  `sandkit_workspaces.metadata` keeps only the current OpenClaw summary.
- Uses `openSession()` for the live phase where OpenClaw actually runs.
- Uses `attachSession()`, `extendTimeout()`, and `commit()` from the session handle.
- Persists Sandkit metadata with `drizzle` + `sqlite`.
- Rewrites OpenClaw Control UI config during `startSession()` so `allowedOrigins` is the exact public sandbox origin, not `["*"]`.
- Uses `gateway.controlUi.dangerouslyDisableDeviceAuth=true` so tokenized remote Control UI access works inside the sandbox example. This is a deliberate security downgrade for the example flow.

`startSession()` reads `openclaw_sessions` and repairs bootstrap artifacts against the current active session row when needed.

In this example, `commit()` is treated as the durable checkpoint that ends the current live session. Provider behavior may differ, but on the current Vercel Sandbox flow the session should be considered finished after commit.

## Setup

```bash
cd packages/sandkit
bun run build

cd ../examples/sandbox-openclaw
bun install
bun run db:generate
bun run db:migrate
bun dev
```

Required environment variables:

- `AI_GATEWAY_API_KEY` (read by host and injected through `aiGateway()`; not written into sandbox config)

Runtime constants in `lib/openclaw-app.ts`:

- AI gateway URL: `https://ai-gateway.vercel.sh/v1`
- AI gateway model: `openai/gpt-5.4-mini`
- OpenClaw install spec: `openclaw@2026.3.13`
- Gateway port: `18789`
- Workspace ID: `openclaw-production`
- Sandbox timeout: `1200000`

Schema generation and migration:

```bash
npx @giselles-ai/sandkit generate --adapter drizzle --dialect sqlite
bun run db:generate # runs drizzle against db/schema/index.ts
bun run db:migrate
bun run db:reset   # remove legacy sqlite and run migration from scratch
```

If migration fails with `no such table` or `already exists`, the local DB state is usually out of sync:

```bash
bun run db:reset
```

`db:reset` removes `data/openclaw.sqlite` and reruns `db:migrate`.
