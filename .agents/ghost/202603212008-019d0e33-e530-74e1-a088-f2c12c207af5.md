This session was not just about adding one more API. The human was trying to make Sandkit prove it can back a production-shaped app, not merely a demo. The strongest pressure was to keep `runCommand()` as the durable, primary path while admitting a live `session` phase for tools like OpenClaw that need a running process, browser access, and attachable operator control. The trap throughout was to simplify toward provider leakage or toy-example ergonomics. Do not do that.

The example work exposed the real shape of the abstraction. A live session is not a free-form shell handle; it is an exclusive lease on a workspace. `runCommand()` remains the durable safety rail. `session` is the explicit live phase. That distinction mattered in both naming and behavior. The OpenClaw example then forced the less glamorous truth: production viability here depends as much on provider details like Vercel Sandbox `ports`, route propagation, and process PATHs as on the high-level API shape. Future agents should preserve that honesty rather than smoothing it over.

- **Context**
  - User goal: make Sandkit support a production-credible OpenClaw control plane on Vercel Sandbox, while preserving `runCommand()` as “1 command = durable commit”.
  - Project context that mattered:
    - `packages/sandkit` now has a session API layered beside the durable command path.
    - `examples/sandbox-openclaw` is intended to be both a correct Sandkit usage sample and a practical app, not a throwaway demo.
    - The repo expects ghosts to preserve lifecycle and persistence judgment, especially around sandbox semantics.

- **Decisions**
  - Decision: keep `workspace.sandbox.runCommand(...)` as the primary durable API, and model live usage through `openSession()` / `attachSession()` / `commit()`.
    - Why: the human explicitly wanted durable units of work preserved, with session as the escape hatch for long-running interactive workloads.
    - Rejected: collapsing everything into a lower-level raw sandbox/session handle, or naming the public API after Vercel snapshot semantics.
    - Strength: strong.
  - Decision: public semantics should use `commit`, not provider-specific names like `snapshotAndClose`.
    - Why: Sandkit should not leak Vercel vocabulary into its public surface. Provider-specific stopping behavior belongs in docs/comments.
    - Rejected: naming public API around Vercel snapshots.
    - Strength: strong.
  - Decision: session is an exclusive workspace lease; `runCommand()` must not run while a live session is active.
    - Why: mixing durable command commits with a live sandbox causes semantic drift and breaks the OpenClaw use case.
    - Rejected: allowing `runCommand()` to race with an active session.
    - Strength: strong.
  - Decision: `session.commit()` should return `void` publicly.
    - Why: the current model advances workspace durability state; commits are not yet first-class public artifacts.
    - Rejected: returning a public durable artifact too early and leaking provider/snapshot identity.
    - Strength: strong.
  - Decision: expose active lease timing as session state.
    - Why: a production control plane needs remaining runtime / expiry visibility.
    - Rejected: hiding runtime expiration and only modeling restorable state.
    - Strength: strong.
  - Decision: for `examples/sandbox-openclaw`, use monorepo package consumption (`sandkit: "workspace:*"`), not `../../packages/...`.
    - Why: the example must behave like a real consumer, or it does not prove package usability.
    - Rejected: path imports and Next-specific rescue config as the long-term answer.
    - Strength: strong.
  - Decision: `startSession` in the OpenClaw example must be recovery-oriented, not “always open a fresh session”.
    - Why: real failures left active leases with missing bootstrap artifacts or dead processes; the control plane must repair this state.
    - Rejected: failing hard whenever a lease already exists.
    - Strength: provisional in implementation shape, strong in intent.

- **Guardrails**
  - Do not collapse `session` back into a generic raw sandbox handle. The point is exclusive live phase semantics on top of a durable workspace model.
  - Do not make `runCommand()` coexist with an active session. That prohibition is not incidental; it protects the model.
  - Do not remove Vercel `ports` handling from the driver. Public route creation depended on it.
  - Do not assume localhost readiness implies public route readiness. Vercel route propagation needed its own wait path.
  - Do not remove the OpenClaw `allowedOrigins` rewrite on session start. The UI looked “white” / unusable until the real public origin was installed.
  - Do not simplify away the launcher PATH fix unless you have verified Node resolution inside the sandbox process environment.
  - Do not regress the example into `../../packages/...` consumption just because package typings are annoying. Fix package/export typing instead.
